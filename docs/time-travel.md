# Time Travel

Time Travel 为每个用户回合记录工作区检查点，并把请求、助手回复、工具结果与代码状态放在同一条时间线上。它解决的是"改坏了想回到某一轮之前"的问题：可以只恢复工作区文件，也可以只切换对话分支，或先恢复文件再切换对话。

该功能默认关闭。开启后只对之后的回合生效；开启前没有保存的代码无法补录。它适合在重构、批量修改或让 Agent 连续执行多步操作时保留可回退点，不替代 Git 提交，也不是外部系统的事务备份。

## 开启与确认

有两个入口：

- 在会话标题栏点击 **Time Travel**，未开启时显示 **开启**。
- 在会话历史页的 Time Travel 区域点击 **了解并开启**。

两个入口都会先展示风险与代价说明，确认后才写入设置。设置页 **设置 → 常规与通知 → Time Travel** 的开关复用同一个确认对话框，不会跳过说明。开启后，接下来的用户回合会自动在工作区采集开始前与结束后的检查点；排队中的 steering / follow-up 用户消息在出队前也会形成新的开始边界，因此排队请求同样有可恢复点。

## 时间线与检查点

在会话历史列表点击会话右侧的时间线图标。时间线按时间顺序显示：

- 真实用户请求与助手回复；
- 工具调用与结果；
- 代码检查点，以及恢复前自动生成的备份；
- 会话分支及当前所在位置。

可以加载更早的记录，也可以切换要查看的历史分支。分支下拉只改变时间线的查看范围，不移动真实会话；只有执行"恢复对话"才会切换分支。旧会话仍可查看消息，但开启前没有保存的代码不能补录，界面会说明当前分支尚未有检查点。

已归档会话可以查看时间线；要恢复对话，需先取消归档。

## 恢复方式

恢复对话框提供三种模式：

| 模式 | 行为 | 失败时的处理 |
|---|---|---|
| **恢复代码** | 将整个工作区内纳入快照的文件恢复到所选检查点；对话留在当前位置 | 显示错误；已写入的部分按备份回滚 |
| **恢复对话** | 在同一个会话中切换到所选位置，后续内容保留在原分支；文件保持现状 | 不修改文件；切换被取消时停留在原位置 |
| **恢复两者** | 先恢复文件，再切换对话 | 若对话切换失败，界面明确说明代码已恢复、对话未恢复，备份仍保留 |

恢复代码前会先读取预览，列出将新增、覆盖和删除的文件。确认期间如果工作区发生变化，预览版本失效，必须重新预览才能继续。执行前会自动采集一份 **恢复前备份**；它会出现在该会话的各分支时间线中，用于找回本次覆盖前的文件。快照损坏会在写文件前被拒绝；写入中途失败时尝试用备份回滚，并在结果中说明是完整回滚还是需要手动使用备份。

恢复过程会串行化同一环境的设置、采集与清理。恢复开始前应暂停同工作区的其他会话、后台作业和外部编辑，避免它们与恢复同时写文件。恢复代码不会提交 Git、不移动 `HEAD`、也不修改暂存区。

### 无法撤销的内容

Time Travel 只覆盖工作区文件与会话分支。数据库变更、网络请求、已经发送的消息、已启动的外部进程和其他副作用无法撤销。恢复代码也不会恢复被排除规则跳过、或从未进入快照的文件。

## 文件范围与开销

快照覆盖整个工作区，因此也会包含手工编辑和其他会话的修改：

- Git 工作区使用 `git ls-files --cached --others --exclude-standard`，保存已跟踪文件和未忽略的新文件。
- 普通文件夹遵循各级 `.gitignore`，并默认排除 `.git` 与 `node_modules`。
- 额外排除规则在设置中逐行填写，使用 Git ignore 语法；规则在采集和恢复时都生效。
- Git 元数据始终排除。空目录不单独保存。

文件读取、哈希和压缩会消耗时间、CPU 与磁盘。大文件多的项目开销更明显；未变化的文件在后续回合可复用已缓存的哈希，减少重复压缩。文件内容按 SHA-256 去重并以 gzip 存储，未被排除的敏感文件也会进入快照，因此应把密钥、构建产物和大数据目录加入排除规则。

快照保存在各执行环境的 Harness 配置目录下 `time-travel/v1/`，不会上传到模型服务，也不在本机与远程 Host 之间传输代码副本。每个执行环境独立保存自己的快照。

时间线读取的是轻量摘要，新检查点只读取上一份完整快照计算变化，恢复时读取所选快照。旧检查点首次查看时会逐个建立摘要缓存，可能出现一次等待；摘要建立后，历史列表不会同时把所有检查点的完整文件清单载入内存。

检查点不是运行中工作区的原子文件系统快照：外部程序可以同时写文件。采集期间检测到文件变化时，该检查点失败并提示，对话仍可继续。不要把检查点当作外部系统的事务备份。

## 设置、保留期限与远程环境

在 **设置 → 常规与通知 → Time Travel** 调整：

| 设置 | 默认值 | 说明 |
|---|---|---|
| 启用 Time Travel | 关闭 | 关闭后停止新快照与自动清理，隐藏时间线和恢复按钮；旧快照保留 |
| 快照保留期限 | 永久 | 可选 30、90、365 天或自定义天数；启用期间在快照边界按天清理过期快照 |
| 额外排除规则 | 空 | 每行一条 Git ignore 规则，可在开启前配置 |
| 快照存储 | 当前环境 | 显示检查点数量与实际占用；清除需要再次确认，并包括恢复前备份 |

共享内容按哈希存储；过期检查点删除后，只有不再被任何快照引用的内容才会被清理。关闭 Time Travel 不会自动删除旧快照，可在设置中手动清除。

设置同步到已连接的远程 Host；未连接环境在重连时同步。设置页会显示未同步或旧 Host 状态，旧 Host 需要更新。正在执行的恢复会先完成，再应用关闭操作。恢复对话需要支持精确分支恢复的 Runtime；不支持时会提示升级 Runtime。

## 限制与本地验收

- 开启前未采集的代码无法补录。
- 恢复对话不修改文件；恢复代码不移动对话。
- 已归档会话必须先取消归档，才能恢复对话。
- 同一工作区的并发写入、外部编辑和后台作业可能使采集失败或让恢复结果与预览不一致。
- 快照不包含 Git 元数据、被排除文件、空目录和运行中的外部状态。

开发服务器的 `time-travel-harness.html?preview=1&marks=off` 使用正式组件与静态 fixture，可检查开启、恢复确认、存储管理、深浅主题和窄窗口；预览按钮只改变本地界面。

核心行为覆盖在 `time-travel-store.test.ts`、`time-travel-service.test.ts`、`time-travel-port.test.ts`、`session-archive-reader.test.ts`、`TimeTravel.test.tsx`，以及 Runtime 的 `harness-time-travel*.test.ts`。实际远程部署、macOS 文件系统行为和真实 SSH 连接仍需在相应环境验证。
